# 🤖 Multi-Robot Cooperative SLAM and Autonomous Navigation with Dynamic Obstacle Avoidance

This project implements a **multi-robot cooperative system** capable of autonomously mapping and navigating an unknown environment using **ROS 2 Jazzy** and **Gazebo Ignition**.  
The system is divided into two main sections:

1. 🗺️ **SLAM Section** – Each robot performs SLAM using `slam_toolbox`, while a map merging node fuses all individual maps into a single global map.  
2. 🧭 **Navigation with Fusion and Prediction Section** – Robots use the shared map to autonomously navigate while dynamically predicting and fusing information about moving obstacles.

## 🐳 Running the Project via Docker
1️⃣ Clone the Repository and Build the Docker Image
```bash

git clone https://github.com/christian-ronchi/Multi-Robot-Autonomous-Navigation.git
cd docker_ws
chmod +x build.sh
./build.sh
```
2️⃣ Run the Container
```bash
./run.sh
```
3️⃣ Build Inside the Container
```bash
colcon build
source install/setup.bash
```
🌍 Switching Simulation Environments
To run the simulation in a different Gazebo world or with a different map:

```bash

# Custom world
ros2 launch multi_robot_bringup tb3_world.launch.py world:=/path/to/your/world.world

# Custom map
ros2 launch multi_robot_bringup tb3_nav2.launch.py map:=/path/to/your/map.yaml
```
🔧 Performance Tips
🧩 Limit the number of active robots if performance drops (2–3 robots recommended).

🖥️ Disable the Gazebo GUI by commenting out gzclient_cmd in the world launch file.

⚙️ Lower physics update rates in your .world file:

```xml
<physics type="ode">
  <real_time_update_rate>100.0</real_time_update_rate>
  <max_step_size>0.01</max_step_size>
</physics>
```
📉 Reduce topic frequencies (e.g., /odom, /scan, /tf) if high bandwidth is unnecessary.


## ⚙️ 1) SLAM Section

During this phase, multiple **TurtleBot3** robots cooperatively explore an unknown environment to build a shared global map.

<details>
<summary>🧩 <b>Architecture Overview</b></summary>

- Each robot runs a **slam_toolbox async online mapper** instance within its namespace.  
- The number of active robots and their initial poses are defined in `multi_robot_bringup/config/robots.yaml`.
- A **Gazebo-ROS bridge** is created for each robot, using the configuration defined in `gz_bridge.yaml`.
- Individual maps are generated by each robot and fused into a single global map using the **robust_map_merger** node from the `merging_pkg`.
</details>

<details>
<summary>🗺️ <b>Map Merging and LiDAR Filtering</b></summary>

- `robot_laser_filter` removes LiDAR beams that hit other robots, preventing false map readings.  
- `robust_map_merger` combines all the maps into a unified map published on the `/map_merged` topic.
</details>

### 💾 Saving the Final Map

Once exploration is complete, the global map can be saved in two ways:

#### Manual Save
```bash
# 1. Change directory for saving maps
ros2 param set /robust_map_merger save_directory "/root/Desktop/maps"

# 2. (Optional) Set custom map name
ros2 param set /robust_map_merger map_name "mappa_laboratorio"

# 3. Save the merged map
ros2 service call /save_merged_map std_srvs/srv/Trigger "{}"
```
#### Automatic Save
The map is automatically saved when the system is shut down via keyboard interrupt (Ctrl + C).

🚀 How to Run the SLAM Section
```bash
ros2 launch slam_multi_robot general_bringup.launch.py
```
This launch file automatically starts:

Gazebo simulation and per-robot bridges

slam_toolbox mapping nodes for all enabled robots

Map merging and LiDAR filtering nodes

RViz visualization for monitoring the mapping process

Monitor the Merged Map
```bash
ros2 topic echo /map_merged
```
Save the Final Map
Use the manual or automatic method described above.

## 🧭 2) Navigation with Fusion and Prediction Section
In this phase, the robots can use the previously generated shared map to navigate autonomously in an environment populated by dynamic obstacles.

<details> <summary>🧠 <b>Dynamic Obstacle Prediction and Fusion</b></summary>
The dynamic_obstacle_detector package provides real-time detection and motion prediction of moving obstacles.

The obstacle_fusion package fuses obstacle information from multiple robots to form a consistent, global representation of the environment.

This allows each robot to plan and adjust its navigation path proactively, avoiding both static and dynamic obstacles.

</details> <details> <summary>🗺️ <b>Map and Navigation Setup</b></summary>
The global map obtained from the SLAM phase can be used as the environment reference.

The multi_robot_bringup package launches the Nav2 stack for each active robot, enabling goal-based navigation and autonomous path planning.

The RViz configuration allows real-time visualization of both robot trajectories and predicted obstacle motion.

### 🚀 How to Run the Navigation Section
</details>

1️⃣ Launch the Gazebo Simulation
```bash
ros2 launch multi_robot_bringup tb3_world.launch.py
```
2️⃣ Launch Nav2 and Dynamic Obstacle System
```bash
ros2 launch multi_robot_bringup tb3_nav2.launch.py
```
3️⃣ Set Navigation Goals
Use RViz to set navigation targets.
Robots will navigate cooperatively while dynamically avoiding predicted obstacles.

⚙️ Robot Configuration
Robots are defined in config/robots.yaml, specifying their namespace, initial pose, and whether they are active:

```yaml

robots:
  - name: tb1
    x_pose: "0.5"
    y_pose: "-0.5"
    z_pose: 0.01
    enabled: true
  - name: tb2
    x_pose: "-1.5"
    y_pose: "0.5"
    z_pose: 0.01
    enabled: false
  - name: tb3
    x_pose: "-0.5"
    y_pose: "-0.5"
    z_pose: 0.01
    enabled: true
```
💡 Robots can be easily added, removed, or repositioned by editing this configuration file.
